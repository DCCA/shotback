# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Required reading before edits

Read `FIREHOSE.md` before making any change — it is the project's operating contract (OpenSpec-lite: fluid, iterative, brownfield-first, one logical unit of work per change). If `FIREHOSE.md` conflicts with another local guideline, `FIREHOSE.md` wins unless the user overrides it. `AGENTS.md` and `CONTRIBUTING.md` restate the same workflow.

Non-trivial work is tracked as a change folder under `.docs/`: `proposal.md` (why/scope), `spec.md` (RFC-2119 requirements with Given/When/Then scenarios), `design.md` (how), `tasks.md` (checklist). Move `todo/ → doing/ → done/` and add a `completion-summary.md` when finishing. `.docs/PRD.md` is the product entry point. `.docs/` is source-of-truth — never gitignore it.

## Commands

- `npm run check` — the gate: `typecheck && lint && test && build`. Run before any PR.
- `npm run dev` / `npm run build` — Vite dev server / production build into `dist/`.
- `npm run test` — Vitest unit tests (`vitest run`, scoped to `tests/**/*.test.ts` by `vitest.config.ts`). Single file: `npx vitest run tests/capture.test.ts`. Single test: `npx vitest run -t "name substring"`. Watch: `npx vitest`.
- `npm run test:e2e` - Playwright end-to-end smoke test (`tests/e2e/extension.spec.ts`, config `playwright.config.ts`). Builds `dist/`, then launches **real Chromium in new-headless with the unpacked extension loaded** (`--load-extension`) and asserts: the extension/service worker loads (no popup, `downloads` permission), the on-page capture notice shows → hides cleanly → is removed (driven through the real content script via `SB_CAPTURE_*` messages), a real full-page capture stitches every viewport in order (checked by pixel hue) on a `scroll-behavior: smooth` page and on an inner-scroller page, the copied prompt carries the captured tab's environment, per-annotation geometry, the element each annotation covers and the `Diagnostics:` block (the fixture server 404s anything that is not a fixture page, and the `smooth` page requests a 1px image that does not exist), _Copy for Claude Code_ writes a JSON sidecar the test reads off disk and parses (located by MIME type, because Playwright renames every intercepted download to a GUID artifact), a redaction drawn over the fixture CTA's label leaves the saved share's pixels there with under a quarter of their fine detail (`pixelDetail`, the mean step between adjacent pixels, which is what pixelation actually destroys) **while a control region just outside it keeps its own** (so "detail collapsed" cannot pass for a blank or corrupted export), and the prompt says `Redacted regions: 1` and nothing else about it, and the editor page renders. Requires a one-time `npx playwright install chromium`. **Deliberately excluded from `npm run check`/CI** (needs downloaded browsers + new-headless) - run it locally on demand.
- `npm run typecheck`, `npm run lint` (`lint:fix`), `npm run format` (`format:check`).
- `npm run gen:icons` — regenerate `public/icons/*` from `scripts/generate-icons.mjs`.

To run the extension: `npm run build`, then load the `dist/` folder via `chrome://extensions` (Developer mode → Load unpacked). `npm run test:e2e` automates the page-side flows and a real scroll-and-stitch capture (the editor opened with `autocapture=1` runs the actual `captureVisibleTab` loop against a smooth-scroll page and an inner-scroller page); what it can't do (clicking the toolbar icon) and the rest of the UI are still verified manually (annotate/comment, timeline select/remove, viewer, cloud-LLM fallback).

## Architecture

A Manifest V3 Chrome extension (TypeScript + React 18 + Vite + Tailwind). Two HTML entry points (editor, viewer) plus two extension scripts, all bundled by `vite.config.ts` (which fixes `background.js`/`content.js` output names so the manifest can reference them). `@/*` aliases `src/*`.

**Three surfaces:**

- The toolbar icon has **no popup**: `src/background.ts`'s `chrome.action.onClicked` handler opens the editor in a new tab with `?tabId=&windowId=&autocapture=1` of the active tab, and the editor auto-captures once on load (one-click capture). The manifest's `commands` entry (`_execute_action` for `Alt+Shift+S`) binds a keyboard shortcut to the same handler.
- `src/editor/main.tsx` — the heart of the app (~1000 lines). Drives capture, hosts the annotation canvas, the comment timeline, general feedback, and the three output actions.
- `src/viewer/` — renders a saved share from `?share=<id>` (local-only page).
- `src/background.ts` - service worker; logs on install and hosts the `chrome.action.onClicked` handler (one-click capture). `src/content.ts` - injected on `<all_urls>`; responds to `SB_GET_PAGE_METRICS` / `SB_SCROLL_TO` / `SB_RESTORE_SCROLL`, to the capture-notice messages `SB_CAPTURE_BEGIN` / `SB_SET_OVERLAY` / `SB_CAPTURE_END`, to `SB_INSPECT_POINTS` (per-annotation DOM context) and to `SB_GET_DIAGNOSTICS` (the page's failed requests).

**Full-page capture flow** (`src/lib/capture.ts`, called from the editor — _not_ from the background): `activateTab` brings the target tab forward → `ensureInjectable` re-injects `content.js` → reads page metrics → `buildScrollSteps` computes viewport-sized scroll offsets → for each step, scrolls the page (via content-script message) and calls `chrome.tabs.captureVisibleTab` → stitches the PNG segments onto a single canvas scaled by `devicePixelRatio`. Restores scroll and the previously-active tab in `finally` blocks. `CaptureResult` also carries a `CaptureEnvironment` - the captured tab's page title, URL, viewport (CSS px), device pixel ratio, colour scheme, scroller kind and user agent plus the capture timestamp - built by the pure, unit-tested `buildEnvironment(metrics, userAgent, now)`. Everything but `userAgent`/`capturedAt` comes from `PageMetrics` (the content script measures the _target_ tab; the editor page has its own title, size and scheme). The editor keeps it in `environment` state (cleared when a capture starts) and hands it to both prompt builders and to `saveLocalShare`, which stores it as an optional passthrough field - no `schemaVersion` bump, absent on older shares.

**Page diagnostics:** right after the metrics read, `captureFullPage` also asks the tab for `PageDiagnostics` via the best-effort `getDiagnostics(tabId)` (`SB_GET_DIAGNOSTICS`; any failure yields an empty list, never a failed capture). The content script computes it on demand from `performance.getEntriesByType("resource")`, keeping entries whose `responseStatus` is 400 or more - feature-guarded on `typeof responseStatus === "number"`, deduped by status+URL, capped at 20, each URL collapsed to one line of 200 chars because it is page-controlled text. It is a **partial view by construction**: `responseStatus` is CORS-gated (0 for a cross-origin response with no `Access-Control-Allow-Origin`, so third-party failures are invisible), a request that never got a response has no status, and the resource-timing buffer holds only ~250 entries - an absent block means "nothing readable failed", never "nothing failed". Do not let a doc or a prompt claim otherwise. It rides on `CaptureResult.diagnostics` into editor state (cleared when a capture starts, like `environment`) and into both prompt builders, which render a `Diagnostics:` block after the `Environment:` block **only at `Detailed` prompt detail, and only when it is non-empty** - so a prompt with nothing to report stays byte-identical to what it was before, and a `Compact`/`Standard` prompt never carries it at all (see the outputs paragraph below). It is deliberately not persisted on shares. **Uncaught page errors are not collected**: Chromium reports an error only to listeners in the world that threw, so the isolated world's `window` listener never sees the page's (measured - see `.docs/done/2026-08-24-diagnostics/`), and catching them would need a `world: "MAIN"` content script on every page load. That is a security-posture decision, recorded in `SECURITY.md`, not an implementation gap to quietly close.

**What gets scrolled:** `content.ts`'s `findScroller` picks the document when it scrolls, otherwise the largest `overflow: auto|scroll` element at least half the viewport tall (SPA shells with `html,body{overflow:hidden}` scroll an inner `<div>`; measuring only `documentElement.scrollHeight` there captured a single viewport). `PageMetrics.fullHeight`/`viewportHeight` are that scroller's `scrollHeight`/`clientHeight` and `scrollerTop` is where it starts in the viewport; `segmentPlacement` (pure, unit-tested) keeps the first frame whole so chrome above the scroller (a header) appears once and crops later frames to the scroller's rows. Scrolls use `behavior: "instant"` so a page's `scroll-behavior: smooth` cannot animate past the frame capture (which stitched the previous viewport twice). The scroller's native scrollbar is hidden (`scrollbar-width`/`::-webkit-scrollbar`) for the duration of the capture and restored afterward, so its track is not baked into the stitched frames.

**One-click auto-capture races two transient Chrome errors** (it fires the instant the editor opens, before the tab strip/content script have settled), handled by retry helpers in `capture.ts`: `activateTab` retries `chrome.tabs.update` past `isTabsBusyError` ("Tabs cannot be edited right now"), and `sendToContentScript` re-injects + retries past `isNoReceiverError` ("Receiving end does not exist"). All four are exported and unit-tested in `tests/capture.test.ts`.

**On-page capture notice:** because capture activates and scrolls the _target_ tab (the user is looking at the page, not the editor), `content.ts` injects a fixed top-of-viewport notice ("Capturing full page… don't switch tabs or scroll"). The orchestrator shows it (`SB_CAPTURE_BEGIN`), hides it for each `captureVisibleTab` frame (`SB_SET_OVERLAY`, acked only **after the next paint** via double-rAF so it never leaks into a frame), re-shows it on each `SB_SCROLL_TO`, and removes it on `SB_RESTORE_SCROLL` / `SB_CAPTURE_END`. Notice messages go through `notify` — best-effort, never abort a capture.

**Per-annotation DOM context:** after every annotation commit the editor (`main.tsx`'s `refreshContexts`) maps each annotation back to the live tab, in **two passes**. First `inspectAnchor` in image px / `CaptureResult.scale` gives a page CSS px point and one `SB_INSPECT_POINTS` round trip carries **all** the points: `content.ts` scrolls the capture scroller quietly (no notice, no scrollbar hiding, the point centred in the viewport so a sticky header cannot answer for it, original scroll restored in a `finally`), runs `document.elementsFromPoint`, skips shotback's own overlay/style nodes, marks the hit element with `data-shotback-hit="<index>"` and describes it as an `ElementContext` (`cssPath`, tag/id/classes/role/testId/text, page-px `rect`). Then `readFiberComponents` runs in the page's **own** JavaScript world (`chrome.scripting.executeScript({ world: "MAIN" })`) to read the React fiber off each marked element and clear the mark - it has to: React hangs its fiber on the DOM node as a page expando, and a content script's isolated world cannot see page expandos at all (`Object.keys(element)` is empty there; the `inner` e2e proves both halves). Results are merged by annotation id through `setAnnotations` **only**: a context is derived data, so refreshing it must never add an undo entry - which does mean an older history snapshot can carry an older context. Guards: only the newest inspection may write (a generation counter in `main.tsx`, so a slow response cannot land on top of a newer commit); the content script returns its `window.location.href` and a mismatch with the capture's `pageUrl` answers every point with `null`; a `null` answer **clears** that annotation's context rather than keeping a stale name; component names are clamped to one line of 50 chars on the extension side, and ids, classes, roles, testids and tag names are clamped to 50 chars too, since all of it is page-controlled text. The editor stamps `data-sb-inspect-gen` on its own `<body>` after each inspection writes back - purely a test hook, so the e2e can wait for a round trip instead of racing it. Best effort end to end: a closed tab, a non-React page or a missing content script yields no context (or no component chain), leaves what is stored alone and never surfaces an error. The prompts append ` -> <cssPath>` (and ` in <A > B>` when a component chain was found) to each area-comment line.

**Storage (two-tier, see `src/lib/localStore.ts` + `src/lib/shareDb.ts`):** share _metadata_ (annotations, feedback, page URL, blob key) lives in `chrome.storage.local` under `share:<id>` keys; the large PNG _blob_ lives in IndexedDB (`shotback`/`shareImages`) keyed by `share-image:<id>`. `localStore` is the only module that touches both; it converts dataURL↔Blob, enforces `schemaVersion: 2`, transparently migrates legacy v1 records (inline `imageDataUrl`) on read, and prunes via `DEFAULT_RETENTION_POLICY` (50 shares / 30 days) after each save. A share link is `chrome.runtime.getURL("viewer.html?share=<id>")` — intentionally profile-scoped, never a public URL.

**Undo/redo** (`src/lib/history.ts` + `useEditorState`): `annotations` stays the live in-gesture state; only completed edits are snapshotted into `history`. Commit points are the canvas's `onCommit` (pointer-up after a create, move or resize - a plain selection click does not commit), the inline comment editor when it is left with a pending edit - on `onBlur` **and** on the effect cleanup that runs when the selection changes or the textarea unmounts, because clicking empty canvas removes it without React ever dispatching a blur (one entry per editing session, not per keystroke) and `removeAnnotation`, which every delete path goes through (Delete/Backspace, "Delete Selected Item", the timeline's "Remove"). A new capture calls `resetAnnotations`, which clears the history too. Both the annotations and the history are mirrored in refs that every write updates, and handlers read those refs rather than the render values - a commit can arrive from a passive effect, and the very next keypress must see it before React has re-rendered. `undoAnnotations`/`redoAnnotations` set the history and the live annotations together and drop the selection when the selected annotation is no longer there; the sidebar's Undo/Redo buttons and one window keydown listener in `annotation-canvas.tsx` (Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z or Ctrl/Cmd+Y, ignored while typing in a field) are the only callers.

**Pure, unit-tested helpers** (these are where the real logic and the tests live — `tests/*.test.ts` mirror them):

- `src/lib/crop.ts` - `Rect`, `MIN_CROP_SIZE` (24), `clampCrop(crop, image)` (whole px, at least the minimum per side, fully inside the image - applied both where a crop is created and again at export time) and `applyCrop(annotations, crop)`: shifts annotations from capture space into crop space, clamping a box to the visible part of itself, keeping an arrow when **either** endpoint is inside (shifted, never clipped - clipping would move the head, which is what an arrow points at), keeping a text when its anchor is inside, and dropping everything else. Ids, comments and contexts survive; only coordinates change, and numbering is re-derived downstream so a dropped annotation leaves no gap.
- `src/lib/annotate.ts` - `exportAnnotatedImage` rasterizes annotations onto the screenshot as **numbered pins** (circle + number at `pinCenter`, sized by `pinRadius`) and appends a **"Notes" legend footer**: one row per numbered annotation, led by the same coloured pin and carrying `noteText` (the prompt's own wording, placeholders included), then the general-feedback paragraph. `selectFeedbackRenderMode` picks footer vs. overlay so the export canvas never exceeds `MAX_EXPORT_CANVAS_HEIGHT`/`AREA` limits (the overlay card renders the same content, truncated). An optional `crop` draws **only** that source rect onto a crop-sized canvas and sizes the pins, layout and footer decision off it - it never calls `applyCrop` itself: the caller passes annotations already in crop space, so the image and the text outputs cannot describe different lists. Redactions are pixelated onto the base image **before** any of that is drawn (see the Redact paragraph below). `arrowHeadPoints` is exported and drawn by the canvas too (as an SVG `<polygon>`), so on-screen and exported arrowheads cannot drift.
- `src/lib/numbering.ts` - `numberAnnotations` (creation order, the **one** numbering shared by the comment timeline, the prompt, the canvas pins and the exported image; it **excludes redactions**, once, so every one of those surfaces skips them together), `redactions` (the other half of that split, in creation order), `inspectableAnnotations` (what may be mapped back onto the live page - redactions filtered out here rather than at the call site) - with one caveat since crop: it numbers whatever list it is handed, so the editor surfaces number the full list while the exports number the list that survived `applyCrop`; the sidebar says how many are excluded), `pinRadius` (clamped to the capture width), `pinAnchor` (box corner / arrow tail / text baseline start), `inspectAnchor` (the point an annotation _means_ - box centre, arrow tail, text start - fed to `SB_INSPECT_POINTS`), `pinCenter` (that anchor clamped to `[r, width - r] x [r, height - r]`, used by both draw sites so an edge pin is never clipped), `describeGeometry` (box/arrow/text position in image px plus % of page, rounded, for the prompt's per-annotation line) and `annotationBounds` (the rectangle an annotation occupies; a text run is estimated from its length - it lives here rather than in `src/editor/` so `src/lib/sidecar.ts` can use it without `lib` importing `editor`).
- `src/lib/feedback.ts` - `buildExternalLlmPrompt` / `buildClaudeCodePrompt` (the structured prompts copied for the cloud-LLM and Claude Code exports; both take an optional `CaptureEnvironment` and an optional `PageDiagnostics`, plus an optional `Verbosity` (`"compact" | "standard" | "detailed"`, default `"standard"`) that controls how much of that context actually renders - see the outputs paragraph below), `annotationSummary`, and `noteText` - the single wording for an annotation's note, shared with the exported legend and with the JSON sidecar. `buildClaudeCodePrompt` also takes an optional `sidecarPath` and renders the `Machine-readable annotations (selectors, rects, diagnostics): <path>` line right under the image path, omitting it entirely when no sidecar was written.
- `src/lib/prefs.ts` - `getPrefs()`/`setPrefs(partial)`, a thin `chrome.storage.local["prefs"]` wrapper (tolerates a missing or corrupt stored value, merges a partial write) in the style of `localStore.ts`'s storage helpers. Currently holds one field, `promptVerbosity`.
- `src/lib/capture.ts` - `buildScrollSteps` (scroll offsets), `segmentPlacement` (where each frame lands on the stitched canvas), `buildEnvironment` (page metrics + user agent + `now` -> `CaptureEnvironment`) plus the retry helpers/guards `activateTab`, `sendToContentScript`, `isTabsBusyError`, `isNoReceiverError`, the best-effort `inspectPoints(tabId, points, pageUrl)` and `getDiagnostics(tabId)` wrappers and `readFiberComponents` (the self-contained function injected into the page's own world - it must reference nothing outside itself, because Chrome serializes its source).
- `src/lib/dom-context.ts` - `cssPath` (id-anchored, class-annotated, `nth-of-type` chain, five levels deep, every page-controlled token clamped to 50 chars) over the structural `ElementLike`, so it runs in plain Node with no DOM types. `content.ts` is the only place that adapts a real element into that shape.
- `src/lib/sidecar.ts` - `buildSidecar` builds the `Sidecar` JSON written beside the PNG for the Claude Code handoff: `version: 1`, the capture metadata, the annotations numbered by `numberAnnotations` (so the JSON, the prompt, the pins and the timeline agree), each with `noteText`, an `annotationBounds` `rect` in image px, a `normalizedRect` (0..1 of the image, 4dp, `0` rather than `Infinity` when no capture has sized it yet) and the `ElementContext` when one was read, plus a `redactions` array (`{ tool, rect, normalizedRect }`, no `n`/comment/context, omitted when nothing was hidden), the `environment`/`diagnostics` passthroughs and the relative `imagePath`. Pure: every value comes from the caller, and optional fields are omitted rather than serialized as `null`.
- `src/lib/wslPath.ts` — `toClaudePath` translates a Windows path to its WSL `/mnt/<drive>/…` mount for the Claude Code export.
- `src/lib/boxResize.ts` — box drag/resize geometry.
- `src/lib/history.ts` - `createHistory`/`commit`/`undo`/`redo`: a generic snapshot undo stack (`{ past, present, future }`, 100 entries by default). `commit` is a no-op when the value is the same reference, so a double commit costs nothing.
- `src/lib/editor-placement.ts` - `placeInlineEditor` puts the inline comment editor below the selected shape (left-aligned, flipped above near the bottom edge, clamped inside the image) from the shape's `annotationBounds` (`src/lib/numbering.ts`), so the editor never covers what it comments on.
- `src/lib/selectNavigation.ts` — `getNextIndex`/`matchTypeahead` keyboard-navigation rules for the custom `Select` listbox (so the interaction logic is testable apart from the DOM).
- `src/types/annotation.ts` - the `Annotation` discriminated union (`box` | `arrow` | `text` | `redact`), plus `RectAnnotation` (`box | redact`, the two that are plain rectangles and share the drag/resize path).

**Design system (`src/components/ui/*` + `src/styles/globals.css` + `tailwind.config.js`):** components are driven by semantic HSL **CSS-variable tokens** (`--primary`, `--secondary`, `--muted`, `--accent`, `--destructive` + `-hover`, `--border`, `--input`, `--ring`, plus `--glow-1`/`--glow-2` for the body gradient and `--card-highlight`/`--card-shadow`/`--button-highlight` for elevation) mapped to Tailwind color utilities - use `bg-primary`/`border-input`/`ring-ring` etc., never hardcoded `emerald-*`/`slate-*`/`bg-white` literals, anywhere in `src/` (`grep -rnE "(text|bg|border|ring|from|to|via|fill|stroke)-(slate|emerald|red|white)\b" src/` must stay at zero hits; the `hover:`/`focus:` variants are covered because the prefix still follows the colon). **Dark applies two ways:** automatically from `@media (prefers-color-scheme: dark)` on `:root:not(.light)`, and explicitly via `class="dark"` on `<html>`; `class="light"` forces light back on. The two blocks hold the same 27 custom properties plus `color-scheme` and are **deliberately duplicated** - `light-dark()` returns a colour rather than the bare HSL channels the tokens interpolate (breaking `bg-primary/40`-style alpha modifiers) and an inline pre-render script is forbidden by MV3's CSP. Both live **outside `@layer base`** so Tailwind does not tree-shake the unreferenced selectors. `tests/e2e/extension.spec.ts` guards a slice of this: "dark theme keeps every control legible" loads an **empty** `editor.html` with `colorScheme: "dark"`, walks every `button, p, span, h1, h2, label` that has text, and fails if its colour is within 0.3 luminance of the nearest painted ancestor background, or if the body background is still the light value. It never mounts the comment timeline, saved shares, the annotation-canvas branch or the viewer - the visual checks recorded in `.docs/done/2026-08-24-dark-theme/completion-summary.md` are the evidence for those. `Select` is a **custom WAI-ARIA listbox** (not a native `<select>`): pass `value` + `onValueChange` + `options`, not `<option>` children - the native option popup is unstylable, which is why it was replaced.

**Redact (hide a region):** the sidebar's Tool select has a `Redact` entry that draws a `RedactAnnotation` (`{ tool: "redact"; x; y; width; height }`) into the same `annotations` array and the same undo history as a box, so it moves, resizes, deletes and undoes exactly like one. Everything else about it is deliberately mute: `numberAnnotations` filters it out (no pin, no timeline row, no legend row, no numbered prompt line), `inspectableAnnotations` filters it out of the inspection list in the lib rather than at the call site (reading the element under it would put its selector and its text into the prompts it exists to keep them out of, so a second call site cannot leak by default), and it gets no inline comment editor - its `comment`/`context` are typed `never`, so the compiler, not the UI, is what enforces "never populated". Picking it forces draw mode the way Crop does, and (also like Crop) an existing annotation does not swallow the pointer-down, so a secret is coverable wherever it sits. On the canvas it is a diagonal SVG `<pattern>` hatch in the annotation colour at 35% opacity: the user can still see what they hid, because the pixels only go for good in the export. **The hiding itself is one place**: `exportAnnotatedImage` draws the base image, pixelates every redaction through a `ceil(w/12) x ceil(h/12)` offscreen buffer (downscaled at `imageSmoothingQuality = "high"` so a block weighs its whole area instead of sampling a pixel out of it, redrawn with `imageSmoothingEnabled = false`), and only then draws annotations, pins and the legend, so nothing can be painted over a secret before it is destroyed. Since **every** output is that function's data URL - download, Copy Image, the cloud package, the Claude Code PNG and the image `saveLocalShare` stores - there is no path a raw capture can leave by. `applyCrop` shifts and clamps a redaction like a box. The prompts add one `Redacted regions: N` line at **every** verbosity (a safety fact is worth one line even in `Compact`), and the sidecar lists them under `redactions` as `{ tool, rect, normalizedRect }` with no `n`, comment or context. `SECURITY.md` carries the honest statement of what that does and does not protect: the unredacted capture lives only as the editor tab's in-memory `baseDataUrl` and is gone when the tab closes.

**Crop (region export):** the sidebar's Tool select has another entry, `Crop` (`EditorTool = AnnotationTool | "crop"` in `use-editor-state.ts` - nothing stored in an `Annotation` can ever be a crop). Drawing with it sets `cropDraft` (clamped by `clampCrop`, discarded under `MIN_CROP_SIZE`); the sidebar then offers **Apply crop** / **Cancel**, and once applied shows `Cropped to WxH` with **Clear**. Both `crop` and `cropDraft` live **outside** the annotation history, next to `zoom`: a crop is a view onto the capture, not an edit of it, so undo never steps through one - and a new capture clears both (`main.tsx`). The canvas dims everything outside the region and outlines it (`#crop-region`); the marquee is not an annotation (no pin, no timeline row, no history entry, no pointer events). **Annotations are stored uncropped**: the shift happens once, at output time, in `exportView(state)` (`use-exports.ts`) - the single derivation every output goes through, handing back `applyCrop(annotations, crop)`, the clamped crop and the crop's size as the reported image size (and, with no crop, the untouched state, so every output stays byte-identical to before). That is also why `refreshContexts` keeps working: it maps `inspectAnchor`/`captureScale` back onto the live tab in **capture** coordinates, which a crop never disturbs.

**Four outputs from the editor:** all four render `exportView(state)`, so an active crop applies to every one of them: (1) _Copy Local Share Link_ → `saveLocalShare` + viewer URL; (2) _Prepare for Cloud LLM_ → downloads the annotated PNG and copies `buildExternalLlmPrompt` output to the clipboard; (3) _Copy for Claude Code_ → saves the PNG **and a JSON sidecar** (`cap-<ts>.png` / `cap-<ts>.json`, same timestamp) to `Downloads/shotback/` via `chrome.downloads`, reads back both absolute paths, and copies `buildClaudeCodePrompt` output with the paths translated by `toClaudePath` (`src/lib/wslPath.ts`, `C:\… → /mnt/c/…`) so a WSL Claude Code session can read the files directly. The sidecar (`buildSidecar`, `src/lib/sidecar.ts`) is the machine-readable half of the same review, and the prompt points at it on its second line (`Machine-readable annotations (selectors, rects, diagnostics): <path>`). It is **best effort**: `saveSidecar` in `use-exports.ts` swallows its own failures, the prompt then simply carries no sidecar line, and the status says so rather than claiming a clean copy. `skills/shotback/SKILL.md` is the companion skill users copy into their own project, telling an agent to read the sidecar instead of pixel-hunting; (4) _Copy Image_ → `copyImage` in `use-exports.ts` writes the annotated PNG straight to the clipboard (`navigator.clipboard.write` with a `ClipboardItem`) for pasting into any agent chat - no download step. The extension makes **no network requests of its own**; data leaves the device only via these explicit manual exports.

Both prompt outputs (2 and 3) are shaped by the sidebar's **"Prompt detail"** setting - `Compact` (numbers, notes, general feedback and the page URL only), `Standard` (the default; everything above plus the `Environment:` block, per-annotation geometry and the element each annotation covers) or `Detailed` (standard plus the `Diagnostics:` block and, under each annotation with one, its element's `text`/`classes`/`rect`). `useEditorState` loads it from `src/lib/prefs.ts` on mount and persists every change, so it carries across sessions; `use-exports.ts` passes it straight through as `verbosity` on both builder calls.

## Conventions

- TypeScript `strict` with `noUnusedLocals`/`noUnusedParameters`; explicit over clever.
- `kebab-case` file names; small, low-blast-radius diffs over broad refactors.
- Keep pure logic in `src/lib/*` (testable, no `chrome.*`); confine `chrome.*` calls to the editor/viewer/background/content boundaries.
- Conventional-commit style messages (`feat:`, `fix:`, `chore:`, `security:`); one logical change per commit.
- Permissions are deliberately minimal (`activeTab`, `tabs`, `scripting`, `storage`, `unlimitedStorage`, `<all_urls>` host access) — see `SECURITY.md` before touching `public/manifest.json`.
